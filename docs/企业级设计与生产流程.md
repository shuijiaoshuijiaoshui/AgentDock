# AgentDock · 企业级设计与生产流程

> 适用范围：架构评审、技术讲解、新人上手、上线前自查。
> 数字口径：以 `docs/STATS.md` 与当前代码为准（11 个服务、8 个域、35 个域内工具、33 类意图、332 个测试）。
> 原则：**只写代码里真实存在的机制**；设计意图与已知缺口分开写，缺口不包装。

## 一、六条企业级设计思想

这一节回答“为什么这么设计”，每条原则都给项目里的落点。

### 1. 确定性优先：模型只负责“理解”和“说话”，不负责“决定”

| 谁做决定 | 怎么做 | 落点 |
|---|---|---|
| 听懂问题 | LLM 输出 `{意图, 槽位, 置信度}` | `orchestrator/graph.py` understand 节点 |
| 调哪些域、什么顺序 | **纯配置路由表查表**（33 类意图） | `orchestrator/route_table.py` ROUTE_TABLE |
| 多域冲突取谁的值 | **纯函数裁决**，禁止 LLM | `orchestrator/arbitrate.py` FIELD_AUTHORITY |
| 说什么话 | LLM 按产物合成，只允许“说”不允许“算” | synthesize 节点 |

为什么企业级必须这样：路由决定权限、成本、审计口径；如果让模型每步自由决定，同一句话两次走不同链，测试没法写、纠纷没法复盘、成本没法预估。**同输入 100 次同一条链**是可测试、可审计的前提。

### 2. 失败也是产物：宁可少答，不给错答案

- 单域不可达/超时/验签失败 → 该域写 `error` 占位，其余域照答，回答里标注“某域暂不可查”（局部交付）。
- 串行链上游否决 → 下游全部标 `cancelled_by_upstream`，不调用、不脑补。
- 交付前校验：任一产物缺“权威域”标注 → **整体拒答**，不给无出处的数字。
- 政策服务不可用 → 售后降级为“按 12 个月估算”，并标记 `degraded`，不编造条款。

企业级含义：**一次回答不完整可以接受，一次回答不可信不可接受。**

### 3. 写操作必须可撤销：幂等 + 确认 + 回滚

| 机制 | 解决什么 | 落点 |
|---|---|---|
| 业务幂等键（会话+动作+单据） | 网络重试/换会话重复提交 → 只产生一笔 | 写工具 + 跨会话重复退款修复 |
| 两阶段确认（payload 哈希 + 一次性 token + TTL） | 防误操作、防重放、防参数被改 | `shared/confirmations.py` |
| 退款一律人工审批 / 改价开票阈值 / 超 5 倍双人复核 / 申请人不可自批 | 防越权动钱 | `shared/risk.py`、`shared/approvals.py`、config 阈值 |
| Saga 逆序补偿（biz_key 幂等） | 写链中途失败不留悬挂状态 | `orchestrator/graph.py` saga_compensate、ROUTE_TABLE SAGA_CHAINS |

企业级含义：**查询错了是体验问题，写错了是事故**；所有写操作在设计阶段就要声明“怎么撤销”。

### 4. 可追溯：一句回答能倒查到来源、路径、责任

三件套联动，共用同一个 `trace_id`：

1. **产物可溯源**：每个结论带 `authority_domain`（谁说了算）、`as_of`（数据时点）、`snapshot_id`（会话快照）；跨域数据时点差超 5 分钟自动标注。
2. **路径可回放**：traceparent 跨进程透传，span 按服务落 JSONL，`GET /api/traces/{trace_id}` 重建调用树（实测跨 console→编排→域→securityd 四进程）。
3. **责任可追责**：审计事件 HMAC 哈希链（prev_hash 环环相扣 + per-tenant head），独立 securityd 单写者，`verify` 全量校验并定位首条被篡改记录。

企业级含义：toB 采购必问“答错谁负责、怎么证明”。**没有审计的 AI 答案不能进业务。**

### 5. 最小权限 + 纵深防御

- 身份只从验签后的 JWT claim 取（tenant/actor/role/scopes），**不接受 metadata 或请求体自称**。
- 全部 SQL 强制 `tenant_id` 过滤；跨租户返回 not_found（不泄露存在性）。
- 工具执行前校验 scope；越权返回结构化拒绝，数据不进入模型上下文。
- PII 三道脱敏：入口、落库前、进 LLM 前（历史块再脱敏一次）；LLM 载荷做键级清洗。
- 前端安全：HttpOnly + SameSite Cookie、CSRF 双提交、CSP 无 inline、动态内容统一 textContent。
- 服务间信任：AgentCard ES256 JWS 签发/验签，验签通过才建 Task。

企业级含义：**权限必须服务端强制，前端隐藏按钮不算权限**；每一层都假设上一层可能被绕过。

### 6. 渐进降级与人工兜底：AI 接不住时体面交接

出口顺序（优先级从高到低）：

```
明确要求转人工 / 命中投诉纠纷高风险词 / 连续碰壁 2 次
        → handoff：9 字段交接包（含真实近 6 轮）→ 坐席队列
低置信 + 判不出意图
        → 一次性澄清（澄清选项过白名单，不足两个直接拒答）
意图未命中 / 置信不足
        → nomatch：拒答 + 可做能力 + 建议转人工，碰壁 +1
```

企业级含义：**兜底不是报错，是设计好的下一跳**；转人工是协议动作（新 Task + 原 contextId），不是 UI 弹窗。

### 2.3 主链路（一条消息的生命周期）

| 步 | 位置 | 做什么 | 审计/trace |
|---|---|---|---|
| ① | 用户 | 带登录态发一句话（HTTP 或 WS） | — |
| ② | console | 验 JWT → PII 脱敏 → 消息落库 → 组装历史（近 6 轮+摘要） | 审计入口事件 |
| ③ | console→编排 | A2A 委托：拉 Card → 验签 → 建 Task；注入 traceparent | `a2a.send` + 根 span |
| ④ | 编排 intake | 再脱敏、高风险词、装载记忆、身份 | `task.submitted/working` |
| ⑤ | understand | LLM 出意图/槽位/置信度；低置信澄清一次 | 澄清写 decision_log |
| ⑥ | route | 查表得 Plan（域列表 + 模式） | `route.plan` |
| ⑦ | advance/domain_call | 按模式发车；域不可达 → error 占位局部交付 | 每域 `a2a.execute` span |
| ⑧ | 域 Agent | ReAct 选工具 → 查权威库 → 产物带 authority/as_of/snapshot | `tool.call` |
| ⑨ | 编排 | 裁决清洗 → 合成 → 交付校验（缺权威标注整体拒答） | `arbitrate.*`、`deliver.*` |
| ⑩ | console | 回答落库、摘要/碰壁计数回写、WS 推送 | 审计收尾 + span 归档 |

### 2.4 域边界判定（为什么是 7 个）

四问，满足两条以上才独立成 Agent：**独占权威数据、独立故障口径、需要多步推理、独立发布节奏**。
结果：商品/订单/履约/售后/财务/政策/客户。订单与履约拆分是因为“订单状态机”和“库存时效”数据、降级口径完全不同；“商品对比”不独立，因为它没有独占数据，只是商品域的 skill。

### 2.5 协议与状态映射（A2A ↔ LangGraph）

| A2A 概念 | LangGraph 对应 | 实现 |
|---|---|---|
| SendMessage 建 Task | `astream`，`thread_id = tenant:task_id` | 执行器统一入口 |
| `input-required` | `interrupt(payload)` | 澄清 / 域追问 |
| 同 taskId 回填 | `Command(resume=text)` | 从 checkpointer 断点续跑 |
| `completed` | 图终态 → DataPart + TextPart | 产物 + 人话摘要 |
| `rejected/failed` | 域权限拒绝/异常 | 不重试，局部交付 |
| `contextId` 多轮 | 会话锚点 + 历史注入 | console 渠道层持会话态 |

## 三、安全设计分域

### 3.1 身份与租户

- JWT 携带 `tenant_id / actor_id / role / scopes`；HTTP 用 Cookie 或 Bearer，WS 用**连接后首包认证**（浏览器 WS 无法带 Authorization 头）。
- 身份只认 token claim；metadata 里自称的 tenant/scope 一律无效。
- 所有表带 `tenant_id`，所有查询强制过滤；跨租户 404。

### 3.2 数据安全

- 入口、落库、进 LLM 前三道 PII 脱敏（手机/证件/银行卡/邮箱）。
- LLM 载荷键级清洗（客户 ID 等敏感键替换）。
- 测试护栏：`assert_no_pii` 断言送进模型的内容不含原始 PII。

### 3.3 写操作安全

| 风险 | 机制 | 参数 |
|---|---|---|
| 重复提交 | 业务幂等键 | 会话+动作+单据 |
| 误操作/重放 | 两阶段确认 | payload 哈希 + 一次性 token + TTL 600s |
| 越权动钱 | 退款一律人工审批；改价/开票阈值 | 改价 500、开票 1000（阈值只决定复核人数） |
| 内部人滥用 | 超 5 倍阈值双人复核 | 申请人不可自批 |
| 同目标重复申请 | 待审批单去重 + 执行联动 supersede | 同订单只留一张 pending；消费时把其余 pending/approved 置为 superseded（同事务），审批队列无悬空待办 |

审批单状态机：`pending → approved → executed / rejected / superseded / expired`。`superseded` 是终态（同目标已有生效结果），不能再被批准或消费。

### 3.4 审计与追责

- 事件覆盖：`a2a.send`、`task.*`、`tool.call`、`arbitrate.*`、`deliver.*`、`approval.*`、`auth.login`、`rate_limit.block` 等。
- HMAC 哈希链 + per-tenant head；securityd 独占写库，业务服务只经 HTTP 调用。
- `verify` 全量校验：改一条或删链尾都能定位。

### 3.5 服务间信任（AgentCard JWS）

- 发布侧：`build_a2a_app` 统一给 Card 附 ES256 签名（kid = key_version）。
- 消费侧：`delegate` 拉卡 → 验签 → 通过才建 Task；失败写审计 `card.verify_failed` → `CardVerificationError` → 编排降级局部交付。
- 缓存：验签通过的 Card TTL 300s；kid 轮换经 `CARD_VERIFY_KEYS_JSON` 新旧公钥并存。
- **边界（如实写）**：当前开发部署所有服务共享同一把密钥，签名只能证明“本系统签的”，不能证明“哪个域签的”；compose 未挂载密钥，需补每服务独立密钥 + 密钥分发才算真正建立服务身份。详见第六节。

### 3.6 可用性兜底矩阵

| 故障面 | 系统行为 |
|---|---|
| 单域不可达/超时/验签失败 | error 占位 → 局部交付，其余域照答 |
| 串行链上游否决 | 下游全部 cancelled_by_upstream，不调用 |
| 写链失败 | Saga 逆序补偿；补偿失败升级人工 |
| LLM 输出不合 schema | 任务失败（当前未降级到规则分类，见缺口） |
| 进程重启 | checkpointer 恢复，同 taskId 断点续跑 |
| 高负载/恶意请求 | 分级滑动窗口限流（HTTP/WS/登录分开） |
| AI 接不住 | 澄清 → 拒答 → 转人工三级出口 |

## 四、生产流程（从开发到上线）

### 4.1 本地开发

```bash
uv sync
cp .env.example .env            # 可先用 LLM_PROVIDER=fake
uv run python scripts/gen_keys.py
uv run python scripts/seed_mock.py
uv run python scripts/dev_all.py   # 10 服务一键起（默认开 trace）
```

约定：LLM_PROVIDER=fake 时全链路可跑、可测、不花钱；每服务独立 SQLite（避免多进程锁）。

### 4.2 质量门禁（三层 + 专项）

| 层 | 内容 | 规模/耗时（本机） |
|---|---|---|
| 单测/合同 | 路由确定性（100 次）、工具合同与越权、裁决、白名单、schema | 64 个 ≈ 2 秒 |
| 真进程 e2e | 全链路、澄清续跑、重启恢复、杀域局部交付、Saga 故障注入、转人工闭环 | 模块级起 3–6 个服务 |
| 浏览器冒烟 | 坐席/主管双视角真实鼠标键盘（CDP）+ 客户侧 UI 契约 | 真实页面 |
| 全量 | 261 个用例 | 100–120 秒 |
| 安全专项 | 跨租户越权 21 例、XSS/CSP 8 例、PII 不进 LLM、审批/确认单 | 随全量 |

门禁规则：提交前全量绿；改路由/意图需同步“三处”（路由表、白名单、prompt 候选）；改 prompt 升版本号（understand@1.5 / synthesize@1.1）。

### 4.3 构建与部署

- Dockerfile：只 COPY 代码目录，**构建期 seed mock 数据**；不把测试和密钥打进镜像。
- Compose：10 应用服务 + Postgres，健康检查 + depends_on；服务间用服务名互调（Card 广播 URL 必须用服务名，这是踩过的坑）。
- 反向代理：`infra/nginx/agentdock-support.conf` 提供 `/support/*` 同源反代示例（含 WS Upgrade、Cookie Path）。
- 配置：全部走 env（`.env.example` 有清单）；`ENV=prod` 拒绝默认密钥，KMS 是显式适配点。

### 4.4 上线前检查清单

- [ ] `ENV=prod`、非默认 `AUTH_SECRET` / `CARD_SIGNING_KEY` / `AUDIT_SIGNING_KEY`
- [ ] 每服务独立 Card 密钥已分发；`CARD_VERIFY_KEYS_JSON` 覆盖轮换窗口
- [ ] Postgres 已就位（TaskStore + checkpointer）；`SHARED_DB_PATH` 指向 securityd 独占库
- [ ] TLS 终止于网关；WS 升级路径与 Origin 白名单已配
- [ ] 限流阈值按租户容量标定；登录接口单独口径
- [ ] 审批阈值与复核角色按客户合同配置
- [ ] 审计链 `verify` 通过；trace 目录已挂共享卷
- [ ] 全量测试绿；fake 与真模型各跑一次冒烟

### 4.5 运行期观测与应急

| 场景 | 动作 |
|---|---|
| 回答可疑 | 用 trace_id 查调用树 → 看 decision_log（裁决/否决/丢弃值）→ 查审计链 |
| 审计疑似被改 | `GET /api/audit/events/verify` 定位首条断链行 |
| 某域异常 | 看该域 span 与 error 占位；确认是否局部交付；必要时摘除路由行 |
| 限流误伤 | 查 `rate_limit.block` 审计，按租户调阈值 |
| 密钥轮换 | 新增 kid 公钥到验签表 → 切签名密钥 → 等缓存 TTL（300s）过期 → 下线旧公钥 |
| 回滚 | 按 tag 回退镜像；prompt_version 随 state/审计可追；数据库变更走向前兼容迁移 |

### 4.6 发布纪律

- 提交信息按 `feat/fix/test/docs(phaseN)`；每个 milestone 打 tag。
- 改 prompt = 改产品行为：升版本号、跑回归、审计里留版本。
- 改路由/意图 = 三处同步 + 更新模拟器与导览文档 + `check_tour` 校验。

## 五、关键流程

### 5.1 正常问答（单域）

```
用户 → console（验身份/脱敏/落库/组历史）→ 编排（intake→understand→route）
→ advance 发一个域 → 域查库出产物 → 裁决 → 合成 → 校验 → console 落库/推送
```

### 5.2 跨域串行 + 上游否决 + Saga

```
改地址：履约查运单 → 已发货？否决，订单域不调用
退款：售后判资格 → 不通过？履约/财务取消
取消退款：订单取消 → 财务退款失败 → Saga 逆序恢复订单 → 合成“已回滚”
```

### 5.3 转人工闭环

```
三类触发 → handoff 组装 9 字段交接包（含真实近 6 轮）
→ A2A 委托 console handoff.accept → 入队 + 会话 pending_handoff
→ 坐席接管（WS 双向 + 工具面板 + AI 助手）→ 交还 AI，同 contextId 回流主链
```

### 5.4 故障场景速查

见 3.6 矩阵；原则是：**查询类降级、写操作回滚、接不住转人工**。

## 七、一页速记（评审/汇报用）

1. **一句话**：一主七子 + 坐席 + 审计；模型只理解与合成，路由查表、裁决查表、写操作可回滚。
2. **三层主干**：接入（console）→ 编排（12 节点）→ 域（7 个，27 工具）；五条横切：一致性、协同、记忆、安全、工程。
3. **四个兜底**：局部交付、澄清一次、拒答转人工、Saga 回滚。
4. **三件追溯**：产物带权威域/时点/快照、trace 调用树、审计哈希链。
5. **两条纪律**：权限服务端强制；没有出处的数字不给。
6. **诚实边界**：密钥分发、离线评测、多实例基础设施是下一步，不是已完成。
