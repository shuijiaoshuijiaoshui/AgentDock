注意点（设计取舍与已知边界）

✅ 工具=skill，一岗一权

Card 的 skill 与 @tool 一一对应（TOOL_TO_SKILL 映射写进 Artifact），权限、补偿、评测都挂这一层——不必一个 skill 起一个进程（PRD 3.3 纠偏后的结论）。七域共 27 个 @tool。
domains/merchandising/tools.py:149

✅ scope 只认 token claim（1A 收紧后）

1A 起 scope 一律来自验签后的 JWT claim（shared/authz.py:105 require_scope），metadata 自称无效；不匹配返回结构化 rejected（不进 LLM 上下文）。合同测试用显式错误 scope 验证拒绝路径；e2e 越权矩阵见 tests/test_authz_idor.py（21 例）。
shared/authz.py:105 · tools.py:33 _rejected

✅ 到手价必标"估算"

promo_evaluate 结果 estimate=True + 摘要带"估算值"——到手价口径权威在财务域（promo_arbitrate 仲裁，arbitrate.py:16 FIELD_AUTHORITY），营销侧数字永不冒充成交价；非权威字段在编排侧被丢弃留档。
