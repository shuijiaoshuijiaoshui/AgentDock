注意点（设计取舍与已知边界）

🔴 metadata 走请求级（踩过的坑）

1.2.3 的 RequestContext.metadata 读 SendMessageRequest.metadata，不是 message.metadata——当初塞错位置，交接包关联不上会话。delegate 已固定发请求级。
a2a_client.py 注释（:110 附近）

✅ Task 先入队契约

直接按旧文档写 execute 会报 "Agent should enqueue Task before…"。执行器统一先 enqueue new_task 再用 TaskUpdater 发事件——图执行器与 HumanDeskExecutor 都遵守。
a2a_langgraph.py:138 附近 · console/server.py:138 附近

✅ SDK 触碰面单点化 + Card 签名单点

1.2.3 已无 A2AStarletteApplication。组装收敛为 create_jsonrpc_routes + create_agent_card_routes → Starlette；card_signing_enabled 时 build_a2a_app 内统一签名——10 个服务一处生效。签名走 SDK 官方 signing 模块（RFC 8785 JCS + PyJWT），不自研规范化。
a2a_langgraph.py:589 · card_signing.py:137

🟡 trace 两个非常规决定

① 不用全局 set_tracer_provider（只能设一次，重初始化静默失效）——自持 provider 实例取 tracer；② 不用 ParentBased 采样器——跨进程父上下文是显式锚定的已采样 SpanContext，ParentBased 会恒放行击穿 ratio，故直接 TraceIdRatioBased（按 trace_id 确定性）。
tracing.py:150 附近注释

✅ 审计单写者（1B）

业务进程 local 模式仅限单测；dev_all/compose 全部 remote——审计/审批/确认只由 securityd :8309 落库，哈希链 prev_hash 环环相扣，verify_chain 定位首条被篡改行。"Trace 可丢弃，审计不可。"

🟡 密钥引导的 dev/prod 分界

Card ES256 密钥：dev/test 缺失时首服务启动自动生成进程间共享文件（O_EXCL 锁防 dev_all 并发）；prod 必须预置（ensure_card_key 直接报错）。历史 HMAC 共享密钥不用于 ES256——对称密钥意味着验签方也能伪造。
