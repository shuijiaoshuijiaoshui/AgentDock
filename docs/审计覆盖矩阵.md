# AgentDock 审计覆盖矩阵

> 目标：回答“谁（tenant/actor/role）在什么链路（trace/context/task）对什么对象（action/target）做了什么”，并能在被改/删时定位。
> 存储：`shared/audit.py` 的 `audit_events`（按 tenant 分别串哈希链）；console 工具面板另保留 `audit_log`（AC-8 历史口径）。

## 1. 事件矩阵

|---|---|---|---|---|
| `auth.login` / `auth.login_failed` | console 登录 | tenant, username/actor, ip, ua, result | 否 | `/api/audit/events` |
| `ws.auth` / `ws.auth_failed` | WebSocket 首包认证 | tenant, actor, role, conversation_id, 失败原因 | 否 | `/api/audit/events` |
| `a2a.send` | 每次 `SendMessage`（console→编排、编排→域、编排→人工坐席） | tenant, actor, target=域 URL, task/context, 文本摘要（脱敏） | 否 | `/api/audit/events` |

## 2. 字段与保留

- 四要素：`tenant_id + actor_id + action + target`；扩展：`actor_role / trace_id / context_id / task_id / ip / user_agent / created_at / prev_hash / entry_hash`。
- 脱敏：`params` 与 `result_summary` 写库前过 `shared/pii.mask_obj`；不存原始 PII。
- 留存：PRD 8.9 要求 ≥180 天；当前开发态不自动清理，生产需分区/归档。
- 校验：`GET /api/audit/events/verify`（按 tenant 分别校验）；console 工具面板旧表 `GET /api/audit/verify`。
- 外部锚定：链尾哈希定期写外部存储（WORM/对象锁）是下一步；否则“整链重写”本地发现不了（故障手册 E4/E5 已标注诚实边界）。

## 3. 已知边界

- 共享审计用 SQLite（`SHARED_DB_PATH`），多进程写靠进程内/文件锁；生产多实例必须换 Postgres + advisory lock 或消息队列。
- 审计写入默认 best-effort（不影响只读业务）；审批相关使用 `strict=True`，写不进去就失败，避免“高风险动作无留痕”。
- Trace 与审计同管道但留存策略不同：Trace 可采样/丢弃，审计不可。
