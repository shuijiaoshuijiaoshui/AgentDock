双端经营助手 · 流程图

消费者侧 = LLM 导购/问答 + 规则化交易办理；商家侧 = 数据经营助手（投流 / 选品 / 竞品）。 两个入口共用一套编排、域工具、权限、审批和审计。

LLM 负责理解与表达 规则 / 路由 / 工具 人工门禁 域数据 / 工具 规划中（Phase 1–2）

2.1 取消订单 + 退款（Saga + 审批）

订单先取消，财务后动钱；退款一律审批；财务失败逆序恢复订单。

sequenceDiagram
  autonumber
  participant U as 消费者
  participant C as console
  participant O as 编排
  participant D as 订单域
  participant F as 财务域
  participant S as securityd

  U->>C: 取消订单 SO-2001 并退款
  C->>O: 鉴权 / 租户 / PII / 限流后转发
  O->>O: understand：intent=cancel_refund，槽位 order_no
  O->>D: order.cancel（biz_key 幂等，记录 prev_status）
  D-->>O: cancelled
  O->>F: refund.settle
  F->>S: 创建退款审批（一律人工）
  S-->>F: pending_approval
  F-->>O: pending_approval
  O-->>U: 已提交审批，告知进度
  alt 审批通过
    S->>F: 恢复执行（approval_id）
    F->>F: 幂等写 refunds(status=settled)
    F-->>O: settled
    O-->>U: 退款完成 / 到账时效
  else 财务失败
    O->>D: order.restore（逆序补偿）
    D-->>O: 恢复原状态
    O-->>U: 失败，升级人工
  end

2.2 改地址（履约先判 + 两阶段确认）

先查履约状态；已发货直接否决，未发货才进订单域确认。

sequenceDiagram
  autonumber
  participant U as 消费者
  participant O as 编排
  participant F as 履约域
  participant D as 订单域

  U->>O: 帮我把 SO-2001 改地址
  O->>F: fulfill.track（判是否已发货）
  alt 已发货 / 已签收
    F-->>O: shipped / signed
    O-->>U: 上游否决，订单域不调用
  else 未发货
    F-->>O: paid
    O->>D: order.amend（第一次，pending_confirm）
    D-->>O: confirm_token + TTL + payload_hash
    O-->>U: 请确认新地址
    U->>O: 确认
    O->>D: order.amend（带 confirm_token）
    D-->>O: 改址成功
    O-->>U: 成功 + 审计
  end

3. 商家侧：数据经营助手，建议 + 人工确认

投流/选品/竞品由规则和营销域工具算数，LLM 解释；计划单确认，预算执行人工；监控是 Phase 2。
