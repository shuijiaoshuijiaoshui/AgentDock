> 面向接手开发/运维的工程师。读完本文应当能：理解系统定位与核心链路、知道所有核心接口、能独立完成日常开发与运维。

## 1. 项目是什么

**一句话**：面向 3C/办公数码分销商的 B2B「商家咨询中台」——下游经销商通过对话入口查询订单、库存、授信、对账、发票、售后，AI 先答（带四类结果卡片），答不了或涉及资金写操作转人工；资金动作一律人工审批；全程审计。

**用户不是消费者，是经销商**：`CU-1001 王小明（金牌，杭州）` 这类账号是分销商的区域经销商/企业采购，特征是授信额度、账期、月度对账、专票、保修责任判定——这正是与普通电商客服的差异点。

**三层组合关系**：

1. 平台 = SaaS 多租户（`t_demo` / `t_other` 两个租户演示，数据完全隔离）；
2. 租户内 = 一家分销商服务多个经销商（共享商品目录/价格政策/授信政策/对账周期/开票主体/售后条款）；
3. 经销商 = 多订单、多对账单、多发票、多工单（按 `customer_id` 串成 360 视图）。

**它不是 ERP/OMS**：它是对话式服务层，架在订单/库存/财务/售后等系统之上，读为主、写必须过门禁。

## 4. 核心业务流程（顺序即代码执行顺序）

> 详细版见 `docs/AgentDock-端到端流程架构图-含兜底机制.html` 与 `docs/flow.html`。

### 4.1 通用主干（任何请求）

```
前端 HTTP POST /api/customer/send（Cookie+CSRF）
→ console：JWT/Cookie 鉴权 → CSRF/限流 → 会话归属校验
→ mask_pii 脱敏 → 落客户消息 → WS 广播
→ _build_history_meta（滚动摘要+近6轮+掉窗轮次，逐条再脱敏）
→ A2A 委托 orchestrator（metadata: trace_id/context_id/customer_id/tenant/actor/history）
→ orchestrator：
   intake（装历史/身份槽位/风险词）→ understand（LLM|规则 → intent+slots+confidence）
   → route（纯函数查 ROUTE_TABLE，置信度<0.6 → nomatch）
   → advance（按 mode 发车）⇄ domain_call（A2A 调域，域内 ReAct+工具）
   → synthesize（权威裁决+合成）→ deliver（来源校验）
→ console：落 AI 消息（meta.cards/pending_actions）+ agent_runs/steps → WS 推送
```

### 4.2 四种调度模式（`advance` 内分支）

| 模式 | 意图示例 | 行为 |
|---|---|---|
| single | order_query / credit_query / invoice_status… | Send 一个域 |
| parallel | warranty_check（售后∥政策∥商品） | 一次 Send 全部域，Reducer 合流 |
| serial | refund_status（售后→履约→财务）、order_amend（履约→订单）、cancel_refund（订单→财务） | 一次只发下一跳；上游否决 → 下游全部 `cancelled_by_upstream` |
| arbitrate | promo_arbitrate（订单→商品∥财务，deps: merchandising←order） | 按 deps 分层；上游产物注入下游槽位（order.sku → 商品域） |

### 4.3 写操作门禁（资金动作）

| 动作 | 门禁 |
|---|---|
| `refund_settle` | **无论金额一律审批**（`shared/risk.py` 已改：阈值只决定 1 人/双人复核，>5×阈值双人） |
| `invoice_issue` | 两阶段确认 + 超阈值（默认 1000）审批（⚠️ 待办：改为一律审批，见 §12） |
| `order_price_amend` | 超阈值（默认 500）审批（⚠️ 待办：改为一律审批） |
| `order_amend` 地址 | 两阶段确认（一次性 confirm_token，客户确认后才 UPDATE） |
| `create_ticket` | 两阶段确认（非金额） |
| `cancel_order` | Saga 正向写，幂等 biz_key（⚠️ 待办：纳入取消+退款整体先审批） |

写工具返回 `pending_confirm` / `pending_approval` → console 落 `pending_actions` → 前端出确认/审批卡 → 客户确认或财务/主管审批后才执行。**审批凭据只从受信上下文注入；⚠️ 已知缺口：模型 tool args 里自带 approval_id 时 `setdefault` 不会覆盖（见 §12 待办 B）。**

### 4.4 人工与复核

- 转人工：意图 `request_human` / 高风险词 / 碰壁≥2 → 9 字段交接包 → `PENDING_HANDOFF` → 工作台「待接入」；
- 坐席接管 → `HUMAN_ACTIVE`；回复走 `/reply` 落库广播（不过 AI）；交还 AI → `AI_ACTIVE`；
- 坐席关闭 → `PENDING_REVIEW`；资金写链完结（`REVIEW_INTENTS = {cancel_refund, refund_settle, invoice_issue, order_price_amend}`）也自动 `PENDING_REVIEW`；
- 主管复核：approve → `CLOSED`；reject → 回 `HUMAN_ACTIVE`；
- 坐席工具：会话摘要、客户 360、Agent trace、驳回并编辑（落 feedback）、内部备注、转交、快捷回复、工单、知识库（agent 只能 draft/submitted；published 仅 supervisor/admin）、统计（supervisor/admin）。

## 8. 安全模型（必须遵守的边界）

1. **身份**：JWT HS256（`AUTH_SECRET`）；HTTP 走 Cookie（HttpOnly+SameSite=Lax，customer/workbench 双面分离）+ CSRF 双提交；服务间走 service token；A2A 转发调用方 JWT（on-behalf-of）。
2. **租户**：所有业务表 `(tenant_id, business_id)` 复合键；跨租户一律 404。
3. **对象归属**：`shared/authz.py`——customer=token.sub；staff 必须显式 `customer_id`；service 必须 `on_behalf_of`。
4. **PII**：入口/落库/历史拼接三处 `mask_pii`；`llm_guard` 字段级脱敏后才进 LLM。
5. **确认/审批**：确认单一次性 token（payload hash 绑定，TTL）；审批单绑定申请人/动作/对象/金额，一次性消费，申请人不可自批，双人复核（>5×阈值）。
6. **审计**：securityd 单写者，HMAC 哈希链（per-tenant head），篡改/删尾可发现；`/api/audit/verify` 全量校验。
7. **前端**：CSP `script/style 'self'`；无 innerHTML/localStorage/内联样式；customer 页 `frame-ancestors 'self'`（可被同源 /portal 内嵌），workbench `'none'`。
8. **Card JWS**：ES256，私钥 `infra/keys/card_signing_key.pem`（dev 自动生成，prod 必须预置）；kid 轮换用 `CARD_VERIFY_KEYS_JSON`；验签失败 → 审计 `card.verify_failed` + 局部交付。

**资金红线（已实现部分）**：`refund_settle` 无论金额一律审批；`restore_order` 拒绝已退款订单；模型 tool args 里的 `approval_id` 目前**仍可能被透传**（待办 B，见 §12）。

### 9.8 常见故障 → 处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `database is locked` / 写入排队 | SQLite 单写者；console/business 库未开 WAL | 降并发重启；根治换 Postgres（§12） |
| 工作台/统计转圈 | 队列/统计 N+1 全量扫 | 属已知性能债（§12），先降数据量或加缓存 |
| 消息 WS 收不到 | 多 worker / 进程内存连接表 | 保持单 console 进程；或做 WS 外置（§12） |
| 401 | Cookie 过期 / 多进程 AUTH_SECRET 不一致 | 统一 .env 后重启 |
| 403 | 越权/角色不符 | 按接口角色表核对（§5） |
| 404 | 跨租户/对象不存在 | 预期行为（不泄露存在性） |
| 429 | 限流（120/min，登录 10/min） | 等窗口或调 RATE_LIMIT_* |
| 审计 503 / strict 失败 | securityd 未起或 SHARED_DB_PATH 不一致 | 对齐 env；高价值动作 strict 必须成功 |
| `card.verify_failed` | 密钥不匹配/kid 未知 | gen_keys 对齐；轮换按 §9.6 |
| LLM 报错 | openai 模式无 Key/网络 | 先切 `LLM_PROVIDER=fake` 排障；`llm_ready` 未做启动校验（已知缺口） |
| 附件 400/403 | 类型/大小/越权 | ≤10MB，png/jpeg/webp/pdf；下载只限本人/有权限会话 |

## 10. 数据库表结构（字段级，以代码 DDL 为准）

> 三个库 + 一个任务库。所有业务表都带 `tenant_id`（复合主键/过滤列）；`created_at/updated_at` 为 UTC ISO 字符串（秒级）。**以代码 DDL 为唯一真值**，本节为带含义的转写。

### 10.0 通用约定

| 约定 | 说明 |
|---|---|
| `tenant_id` | 租户隔离列，所有查询必须携带；跨租户一律 404 |
| `biz_key` | 幂等键，格式 `会话ID:业务号:动作`（如 `c-8f3a:SO-2001:refund`）；写操作判重/补偿定位 |

| `approval_id / confirm_token` | 审批单/两阶段确认单凭据；**只允许受信上下文注入，模型参数自带的一律剥离（待办 B）** |

> 检索口径：`search_clauses/search_knowledge` 采用强证据规则——整词或 2-gram 命中 `title/keywords` 才算候选，正文命中只参与排序（长度 ≥3 的完整词可兜底）；无权威条款时回答明确“未找到权威条款”，知识只作非权威参考。

**政策发布工作流（policy_drafts，权威条款的唯一在线变更通道）**

状态机：`draft → submitted → approved → published`；`submitted → rejected`（终态）。
四眼原则：审批人 ≠ 起草人、发布人 ≠ 起草人；起草/审批/发布仅 `supervisor/admin`（且需 `policy.write`），坐席只读。
发布 = 在 `policy_docs` 插入新版本行 + 把上一版开放区间关闭到新版本生效日前一天；**旧版本只失效不删除**，检索按生效期自动切换。禁止追溯生效（`effective_from < 今天` 返回 409 `backdated`）；新版本生效期必须晚于现行最新版本（`version_order`/`overlap` 409）。

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/policy/drafts` | GET / POST | 列表（可按 status/clause_id）/ 创建草稿 |
| `/api/policy/drafts/{id}` | GET | 草稿详情 + 字段级 diff（vs 当前生效版本） |
| `/api/policy/drafts/{id}/submit` | POST | 起草人提交 |
| `/api/policy/drafts/{id}/approve` | POST | 主管/管理员审批（不能是起草人） |
| `/api/policy/drafts/{id}/reject` | POST | 驳回（可带 note） |
| `/api/policy/drafts/{id}/publish` | POST | 发布为新版本（不能是起草人） |

每次状态迁移写审计：`console.policy_draft_created/submitted/approved/rejected/published`，target=`policy:<clause_id>@<version|draft_id>`。

**政策文档摄入与向量索引（可选链路）**

```
.md/.txt 上传 → 按 `## CLS-xxx 标题` 切分（一条款一草稿，超长按段落分 chunk）
→ 自动关键词（标题 + 2-gram 词频）→ policy_drafts（四眼审批）
→ publish（同事务写 policy_index_outbox）
→ scripts/index_policies.py --drain → 本地 embedding → pgvector policy_chunks
查询：keyword ∥ 向量（租户+生效期过滤）→ RRF → 回 SQLite 取权威行 → top3
```

| 项 | 说明 |
|---|---|
| 上传接口 | `POST /api/policy/documents`（multipart，.md/.txt ≤1MB，supervisor/admin + policy.write） |
| 切分规则 | 标题必须是 `## CLS-006 标题` 或 `CLS-006: 标题`；重复条款/无标题/空正文直接 400 + 行号 |
| 自动关键词 | `auto_keywords()` 确定性生成；草稿阶段可人工修改，不再是发布门槛 |
| 向量表 | PG `policy_chunks(tenant_id, chunk_id PK, clause_id, version, chunk_index, content, embedding vector(512), effective_from/to, content_hash, model_name)` |
| 索引命令 | `uv run python scripts/index_policies.py --rebuild [--tenant t_demo]` / `--drain` / `--status` |
| 检索开关 | `POLICY_RETRIEVER=keyword`（默认）或 `hybrid`；PG/模型不可用自动降级 keyword |
| 本地模型 | `uv pip install -r requirements-embeddings.txt`；默认 `BAAI/bge-small-zh-v1.5`（512 维，ONNX） |
| 一致性 | SQLite 发布成功 → outbox pending；drain 前新政策只能靠关键词命中，`--status` 可看 pending 数 |
| 审计 | `console.policy_document_uploaded`、`policy.index_sync` |

### 12.2 其他已知限制
- **生产模式 LLM 异常无规则降级**（fake 走规则；真模型超时/不合法 → 任务 failed）；
- **Card 密钥 dev 全服务共用一份**：验签只证明“本系统签发”；生产需每服务独立密钥+分发（compose 未挂密钥卷）；
- **OTel**：仅 file exporter + 头部采样；尾采样需 collector；多机需共享 `TRACE_DIR`；
- **assist 历史注入未做**（工作台 AI 查询只绑客户上下文）；
- **性能债**：console SQLite 全局锁；queues/stats/history 存在 N+1 全量扫；messages/audit 无归档；无压测数据；
- **`llm_ready` 未使用**：openai 模式无 Key 不会启动失败，调用时才报错；
- **单 console 进程**：WS/限流在内存，多 worker 会广播丢失——扩容前必须做 WS 外置。
