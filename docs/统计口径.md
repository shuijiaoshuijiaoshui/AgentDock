# 统计口径与复核策略（2B）

> 本文是统计 API（`GET /api/stats/summary`）与自动复核策略的唯一口径；前端看板只做展示，不做计算。

## 复核策略（PENDING_REVIEW 自动触发）

涉资金写链在对话内**完结**（非 pending_approval）后，会话自动 `AI_ACTIVE → PENDING_REVIEW`，
由主管在复核队列批准（CLOSED）或驳回（HUMAN_ACTIVE）。触发意图白名单（`REVIEW_INTENTS`）：

| intent | 写链 |
|---|---|
| `cancel_refund` | 取消订单 + 退款（Saga 正向） |
| `refund_settle` | 退款执行 |
| `invoice_issue` | 开票 |
| `order_price_amend` | 改价（高价值审批后执行） |

实现位置：`console/server.py` 的 `handle_customer_message` 与 `_resume_pending_action`
（审批通过后回到对话执行同样触发）；每条转换写 `conversation.state` 审计。

## 统计口径

数据全部来自真实查询（console.db + securityd 审计链），时间范围按 `created_at` 过滤：

| 指标 | 口径 |
|---|---|
| 会话总数 | 范围内创建的 conversations 数 |
| 承接率 | `1 - 转人工会话数 / 会话总数`；转人工 = audit_events 中 `conversation.state` 且 `state=PENDING_HANDOFF` 的去重会话数 |
| 转人工率 | `转人工会话数 / 会话总数` |
| 平均会话时长 | state=CLOSED 的会话 `closed_at - created_at` 均值（秒） |
| 诉求分布 | agent_runs 按 intent 计数（范围内） |
| 驳回率 | feedback（AI 答复被驳回/修改）条数 / AI 消息条数 |

## 驳回（feedback）

坐席对 AI 答复不满意时 `POST /api/conversations/{cid}/feedback`
（message_id + reason + edited_answer 可选），写 `feedback` 表并审计
`console.feedback`；驳回率分母为同范围 `role='ai'` 的消息数。
